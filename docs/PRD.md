## 3. AI 에이전트의 역할 (학습 목표 정의)

### 3-1. 핵심 경험: 자동 매거진 발행

> **AI가 매주 한 번 새 매거진 이슈(`EditorialIssue` JSON)를 발행. 그 이슈가 홈에 자동 반영.**

이걸 만들면서 손에 익힐 기술 7가지:

1. **LLM Provider 추상화** — Gemini, Mock, (선택) Anthropic 인터페이스 분리
2. **Zod 스키마 검증** — LLM 출력 신뢰하지 않고 검증
3. **Structured Output** — Gemini `responseSchema` 활용
4. **프롬프트 엔지니어링** — 매거진 에디터 페르소나, few-shot 예시
5. **Retry / Fallback 로직** — 검증 실패 시 1회 재시도, 실패 시 안전한 폴백
6. **비용 가드** — 같은 입력 hash 24h 캐싱, 토큰 상한, 일일 한도
7. **Production 운영 감각** — server-only, env 분리, .env.local.example 템플릿, 진단 라우트 production 차단

이 7가지가 이력서에서 *"AI production 경험 있음"* 의 진짜 의미예요. 그냥 *"GPT API 호출해봄"* 하고는 차원이 다름.

### 3-2. 하지 않는 것 (학습 범위 밖)

학습 프로젝트라도 욕심 부리면 끝없어짐. **이건 절대 안 함**:

- ❌ 챗 인터페이스 (학습 가치 추가 적음, 시간 소모 큼)
- ❌ 사진 분석 (비전 모델 비용·복잡도)
- ❌ 사용자 인증 (이번 학습 목표 아님)
- ❌ 개인화 saved-ai 섹션 *(원래 Sprint 3 — 빠짐)*
- ❌ /archive 페이지 *(Sprint 3 — 빠짐)*
- ❌ i18n 구조 *(Sprint 4 — 빠짐)*
- ❌ 평가(Eval) 셋 *(Sprint 4 — 빠짐)*

**원래 Sprint 4까지 4주짜리였던 걸, 학습용으론 Sprint 1+2 2주로 압축.**

## 4. 기술 결정사항

### 4-1. LLM

- **Provider**: Google Gemini (이미 결제 셋업 있음)
- **모델**: `gemini-2.5-pro` (이슈 발행은 빈도 낮으니 좋은 모델)
- **Provider 추상화 유지**: MockProvider + GeminiProvider. 학습 목적이 정확히 이 패턴 손에 익히는 것이라 *반드시* 추상화.

### 4-2. 데이터

- 이슈: `data/issues/*.json` 파일 시스템 (git 커밋)
- 유저 데이터: localStorage (그대로)
- DB·인증: 없음

### 4-3. 호스팅

- Vercel 무료 티어 (배포만 해두기)
- 도메인: 안 사도 됨 (`fassionmap-v2.vercel.app` 으로 충분)

### 4-4. 비용 가드

- Gemini API: 캐싱 + 토큰 상한
- 학습 중 안전선: 일일 $1 (무한루프 방지용)
- 실제 예상 비용: Sprint 1+2 합쳐서 $1 미만

원래 4주짜리를 **2주짜리**로:

### Sprint 2 (1주) — 자동 발행 + 화면 반영
- `data/issues/*.json` 시스템
- `lib/editorial.ts`에 `getCurrentIssue()` 추가
- 발행 스크립트 (`npm run publish:issue`)
- 마이그레이션: 현재 하드코딩 → vol-007.json
- AI 발행 첫 이슈 vol-008 만들어서 실제로 화면에 표시
